# ROADMAP.md — 開発手順と学習計画

各 Phase は **「作るもの」「学ぶこと」「完了条件」「小課題の例」** でできています。
Claude Code は 1 Phase を 3〜6 個の小さなステップに分けて進めてください（CLAUDE.md 2.1 の手順で）。
目安の期間は、週に数回・1 回 1〜2 時間作業した場合です。

---

## Phase 0：環境構築（1〜2 日）

`README_最初に読む.md` の手順で、開発者が自分で行う。Claude Code は詰まったときのサポート役。

- **完了条件**：Unity で空のプロジェクトが開ける／VS Code でスクリプトを開くと補完が効く／GitHub に最初のコミットがある

---

## Phase 1：Unity と C# に慣れる（約 1 週間）

- **作るもの**：ボタンを押すとテキストの数字が増える画面（のちのダメージ表示の練習）
- **学ぶこと**：シーン・GameObject・コンポーネント、MonoBehaviour（`Start`、`Update`）、`Debug.Log`、`[SerializeField]`、Canvas / Button / TextMeshPro、日本語フォントの設定、変数・if 文・メソッド
- **完了条件**：ボタンを押すと「ダメージ 6！」と表示され、HP の数字が減っていく。0 以下で「撃破！」
- **小課題の例**：ボタンをもう 1 つ追加して「回復」ボタンを作る

## Phase 2：カードデータとカード表示（約 1 週間）

- **作るもの**：`Enums.cs`、`CardData`、`CardView` Prefab。初期デッキのカード 3 種と仮部員カード 2 種のアセット
- **学ぶこと**：ScriptableObject、enum、配列、`[CreateAssetMenu]`、Prefab、データと表示を分ける考え方
- **完了条件**：CardData をインスペクターで設定すると、画面上のカードの名前・コスト・説明文・タグが変わる
- **小課題の例**：仮部員カードを自分で 1 枚作る（アセット作成とインスペクター入力だけ）

## Phase 3：デッキと手札（約 1 週間）

- **作るもの**：`CardInstance`、`Deck`、`HandView`。シャッフル・5 枚ドロー・捨て札・山札切れ時の再利用
- **学ぶこと**：`List<T>`、for / foreach、クラスとインスタンスの違い、普通の C# クラス（MonoBehaviour でないクラス）、**初めてのテスト**（EditMode テスト）
- **完了条件**：「ドロー」ボタンで手札 5 枚が並び、「捨てる」で捨て札に行き、山札が切れても引き続けられる。`Deck` のテストが緑になる
- **小課題の例**：シャッフル後に山札の中身を `Debug.Log` で全部表示するメソッドを書く

## Phase 4：戦闘の基本（約 2 週間）

- **作るもの**：`Combatant`、`PlayerState`、`EnemyState`、`EffectResolver`（Damage / Block / Draw だけ）、`BattleFlow`、`BattleController`、`EnemyView`、`HudView`
- **学ぶこと**：継承、プロパティ、C# の event（通知の仕組み）、状態マシン（今がどのフェーズか）、switch 文
- **完了条件**：カードをクリック → 敵をクリックでダメージ。集中力が減る。ターン終了で敵が攻撃してくる。勝ち/負けが判定される（敵 1 体「謎のバグ」）
- **小課題の例**：余裕（ブロック）がダメージを先に吸収する計算を自分で書く（ヒントあり）

## Phase 5：敵のバリエーションと予告（約 1 週間）

- **作るもの**：`EnemyData`、`EnemyAI`、インテント表示、敵 3 種＋ボス、複数体の敵、手戻りカード
- **学ぶこと**：データ駆動設計（コードを変えずにデータで敵を増やす）、剰余演算子 `%`（パターンの繰り返し）
- **完了条件**：3 種の敵とボスが仕様どおりに行動し、次の行動が頭上に表示される
- **小課題の例**：オリジナルの敵を 1 体設計して、データだけで追加する

## Phase 6：独自要素 — 締切・タグ・性格・状態（約 2 週間）

- **作るもの**：締切カウンターと炎上、`TagComboTracker` とタグボーナス、`ConditionChecker` と性格パッシブ、やる気・寝不足、仮部員カード 8 枚すべて
- **学ぶこと**：`Dictionary<TKey, TValue>`、条件分岐の整理、ダメージ計算の順番をテストで守る
- **完了条件**：GAME_SPEC 4 章の仮部員カードがすべて仕様どおり動く。締切を過ぎると敵のダメージが 2 倍になる
- **小課題の例**：新しい条件 `ConditionType` を 1 つ追加する（例：「手札が 3 枚以下」）

## Phase 7：ラン構造 → MVP 完成（約 2 週間）

- **作るもの**：`RunState`、`RunManager`、Title / Map / Reward / Rest / Result シーン、一本道 6 マス
- **学ぶこと**：シーン遷移（`SceneManager.LoadScene`）、シングルトンと `DontDestroyOnLoad`、ランダム（`Random.Range`）
- **完了条件**：GAME_SPEC 8 章「MVP の完成条件」をすべて満たす。**Windows 用にビルドして部員に遊んでもらう**
- **小課題の例**：報酬画面に「スキップ」ボタンを自分で付ける

## Phase 8：本物の部員を入れる＋リファクタリング

- **作るもの**：Google フォームのテンプレート、`MemberCsvImporter`（エディタ拡張）、効果システムの Strategy パターン化
- **学ぶこと**：エディタ拡張、文字列処理（`Split`）、リファクタリング（動きを変えずに中身を整える）、インターフェース / 抽象クラス、ポリモーフィズム
- **小課題の例**：新しい効果を「クラスを 1 つ追加するだけ」で実装し、switch 版との違いを体感する

## Phase 9：演出と仕上げ

- カードを使うアニメーション（コルーチン）、ダメージ数字のポップアップ、効果音、BGM、タイトル画面の装飾

## Phase 10：拡張
